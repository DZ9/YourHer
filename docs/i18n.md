# Language configuration

CompanionKit ships with English (`en`) and Simplified Chinese (`zh-CN`). English is the default. The full interface, dialogs, navigation, status/error copy, chips, date formatting and model reply/letter instructions use the selected language. User-authored and previously generated content is never translated in place.

## Instance configuration

Edit `companion.config.json`, then restart the server:

- `i18n.defaultLocale`: new accounts' initial interface/reply language.
- `i18n.fallbackLocale`: catalogue used for missing messages.
- `i18n.detectBrowserLanguage`: optionally match an enabled locale from `Accept-Language` for new guests.
- `i18n.locales`: enabled codes, display labels, translation file paths, speech locales and `ltr`/`rtl` direction.
- `assistant.name` and `assistant.appearance`: default companion identity and feminine/masculine portrait.
- `brand.name`: browser title and product wordmark.
- `timeZone`: calendar boundaries for moods and letters, and displayed message times.

An alternative config file can be selected with `CONFIG_FILE=/absolute/path/to/companion.config.json`. Translation paths are relative to that config file's directory. The server validates configured defaults and loads only explicitly declared catalogues.

## Add another language

1. Copy `packages/i18n/locales/en.json` to a new JSON file, for example `locales/fr.json`.
2. Translate the **values**, preserving message IDs and placeholders such as `{{count}}`, `{{name}}`, `{{topic}}` and `{{question}}`.
3. Add a locale declaration:

```json
{ "code": "fr", "label": "Français", "file": "locales/fr.json", "speechLocale": "fr-FR", "direction": "ltr" }
```

4. Restart. The language appears in the selector and About settings. Set it as `defaultLocale` if desired.

Most inherited IDs are original Chinese source messages, while new components can use English source messages. This is a source-message catalogue, similar to gettext, rather than a list of language-specific page branches. A complete Chinese catalogue prevents missing Chinese entries from falling back to English; partial new languages intentionally use the configured fallback.

## Runtime behavior

Each profile stores a locale. Switching updates interface text without a full reload, preserves the conversation, updates browser speech language and changes subsequent model response/letter instructions. Existing messages, memories and saved letters remain in their original language. Browser detection affects new guests only; it does not overwrite a user's explicit selection.

The offline model has limited English and Chinese scripts and illustrative extraction patterns. A newly configured third language supports UI/fallback immediately, but natural conversation in that language requires a capable real model. RTL direction is configurable; complex layouts still need native-language visual QA.
